# 多源验证 SOP v1.1 — 必须阅读

## 反媒体夸张：证据登记表
每个重要事实建立一条 `claim_id`，必须包含：claim_type、精确主张、单位及期间、数据 as-of、原始发布时间、来源 URL、publication_date、资料类型、原始来源链 `origin_id`、原文支持段落/页码或表格、处理步骤和置信状态。**新闻媒体报道与其转载站点共享同一 origin_id**。同一机构的多个栏目/记者也不能默认独立。

### 优先级（不能粗暴按来源数量投票）
1. A：公司交易所原始财报、交易所监管问询、政策原始发布机关、司法裁判原文。财务科目优先合并报表，留存页码；出现更正报告，则弃用旧版本或说明追溯调整。
2. B：带数据溯源的结构化数据服务及独立原始渠道（例如竞争对手自己的财报、行业协会样本、统计部门）。应对照 A 逐项复算关键数字。
3. C：券商或专业媒体的原创调查，可提供线索但不能代替财务凭证；记录发布日期和利益冲突。
4. D：社交帖、二次转载、匿名爆料与无文档支撑的二手截图，仅“待核实”，不得直接触发基本面结论。

## 关键验证门槛
- 财报营收/利润/现金流/资产负债，尽可能公司官方披露 + 1 个独立数据来源（例如结构化数据库）；**一致时才称“已交叉核对”**；任何冲突先核对合并报表 vs 母公司报表、亿元/万元、归母净利 vs 扣非、累计季度 vs 单季度、A/H 多上市报表、会计准则、追溯重述。
- 政策必须确认 `issuing_authority`、文号、公告日、生效日、适用的行业或海关税号、细则；草案与已生效政策不可混同。
- 行业龙头事件至少来自当事公司公告或监管文件；媒体传闻必须标记待证实；观察对标的的传导路径（行业需求、份额转移、成本、融资风险）并解释正反面。
- 重大订单、用户、装机量、市场份额：如果无官方数据，标明指标来源、样本覆盖和误差区间；不要以第三方估计当成交割确认订单。
- 合理倍数/市场参数应存储同一行情日期、同一利润口径和剔除异常值规则。多个 AI 模型重复同一条信息不是独立证据。

## 工具范围与限制
`python scripts/check_evidence.py --input examples/evidence-demo.json --output outputs/evidence-check.json`
工具按你提供的**元数据**检验是否有权威来源、独立原始链、同单位同期间、数字矛盾；不会联网打开链接，也无法判定录入的“官方”标签是否真实，因此结果使用 `METADATA_CORROBORATED` 而非 `FACT_VERIFIED`。
`CONFLICT`、`NEEDS_PRIMARY`、`MEDIA_ONLY`、`SINGLE_ORIGIN` 和 `UNSUPPORTED` 对核心结论是阻断项；需由研究 Agent 实际查阅源文件核实后再发布。

对 A 股研究最多常用的易错项：TTM 计算四个独立季度、扣非/归母差异、EV 中少数权益、财务费用与已付利息区别、分红/回购对市值/净债务的影响、定增稀释、拟议/已完成资产注入区别。
